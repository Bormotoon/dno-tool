# kmsvnc для dno-tool

Полные исходники с доработками находятся в отдельном форке
[xp9k/kmsvnc](https://github.com/xp9k/kmsvnc).
Сборка закреплена на commit `9a18e250e7d4063da65f51b39aebe4b50a401088`;
SHA-256 архива проверяется перед распаковкой. Лицензия GPLv3 сохранена.

При наличии локального клона `src/` сборка использует его файлы, исключая `.git`.
Этот каталог не входит в репозиторий dno-tool. Чтобы работать с исходниками:

```bash
git clone https://github.com/xp9k/kmsvnc.git packaging/kmsvnc/src
git -C packaging/kmsvnc/src checkout 9a18e250e7d4063da65f51b39aebe4b50a401088
```

Основа: [isjerryxiao/kmsvnc](https://github.com/isjerryxiao/kmsvnc),
commit `190db24b727e556e234497c1ce38b88cd6668544` от 25.06.2024.
SHA-256 исходного upstream-архива:
`c1bed53c23daecb8cf0d37519180dbbb745d9ef32ef01955a28da9c7723356e3`.

Доработки dno-tool:

- ABGR/XBGR для VAAPI, включая 10-битные буферы Intel/KWin.
- NVIDIA: EGL/GBM импорт DMA-BUF с модификатором, чтение RGBA через GLES.
  При смене framebuffer читается актуальный буфер каждого монитора.
  Выходы объединяются в один рабочий стол по реальной геометрии KWin,
  сервер передаёт стандартную схему ExtendedDesktopSize и имена разъёмов.
- Абсолютная мышь без конфликтующих REL_X/REL_Y, пробуждение через ABS_X.
- Вертикальное и горизонтальное колесо, повторы клавиш, Shift для символов.
- Поиск символов по всем настроенным раскладкам и соответствие Unicode keysym.
- Учёт клавиш и кнопок отдельно для каждого клиента, отпускание при отключении.

## Сборка RPM

Из корня репозитория на Windows:

```powershell
.\scripts\build_kmsvnc.ps1
```

На Linux с Podman или Docker:

```bash
bash packaging/kmsvnc/build.sh dist/kmsvnc
```

Скрипт собирает бинарный RPM и SRPM в закреплённом контейнере ROSA 2021.1
с пакетами из репозитория МОС 12. Контейнер и зависимости требуют сети.
В SRPM входят полные исходники из закреплённого архива или локального `src/`.

Для сборки напрямую сначала клонируйте исходники, как показано выше.
Нужны CMake, GCC, make, pkg-config и заголовки
libdrm, LibVNCServer, xkbcommon, libva, libva-drm, EGL, GLESv2, GBM, json-c:

```bash
cmake -S packaging/kmsvnc/src -B build/kmsvnc -DCMAKE_BUILD_TYPE=Release
cmake --build build/kmsvnc
```

Пакет содержит программу и лицензию. Службу, пароль и порт создаёт мастер
dno-tool. После обновления RPM нужно обновить имя, версию и SHA-256 в
`src/workers/setup/installers/kmsvnc.py`, затем заменить файл в `assets/remote/`.

## Особенности

Ввод идёт через `/dev/uinput`, захват — через DRM. Служба запускается от root.
Для русской клавиатуры используется `XKB_DEFAULT_LAYOUT=us,ru`; активную
раскладку выбирает удалённый графический сеанс. NVIDIA/Wayland автоматически
передаёт полный рабочий стол. Геометрию KWin получает модуль C `screen_layout.c`
через штатные утилиты системы. Для остальных видеодрайверов
сохраняется прежний путь захвата. Параметры `--source-plane/--source-crtc`
позволяют явно ограничить захват одним выходом. Для такого режима
`--input-width`, `--input-height`, `--input-offx`, `--input-offy` задают
соответствие выбранного изображения всему рабочему столу.

Обмена буфером через графический сеанс upstream не реализует. Изменение
разрешения захватываемого экрана требует перезапуска сервера. При DPMS
сохраняется последний кадр, захват возобновляется после пробуждения.

## Проверки сборки 0.0.6-4

На МОС 12 / X11 в VM проверены перемещения и три кнопки мыши, оба направления
прокрутки, латиница и кириллица, Shift/Ctrl/Alt, повторы и отпускание клавиш
при отключении клиента с другим подключённым просмотрщиком.

На МОС 13 / KDE Wayland, GeForce GTX 1060 3GB, драйвер NVIDIA 580.178.04
проверен захват AB30 с модификатором `0x03000000004fe014` через EGL.
Основная служба на порту 5900 передаёт обновляющиеся кадры 2560×1440,
libinput принимает абсолютную мышь, кнопки, клавиатуру и оба направления
колеса. Проверены DPMS и перезапуск с повторным подключением. В конфигурации
с двумя мониторами 2560×1440 выбран первый монитор, а область ввода настроена
на весь рабочий стол 5120×1440 через параметры `--input-width/height`.

## Проверки сборки 0.0.6-5

На том же NVIDIA/Wayland-хосте основной сервер передаёт полный кадр
5120×1440: `HDMI-A-1` слева и `DP-1` справа, каждый 2560×1440.
Проверены содержимое обеих областей, ExtendedDesktopSize с двумя мониторами
и координаты абсолютного ввода по всему рабочему столу. Ручная настройка
ширины ввода больше не требуется. Фронтенд, Veyon, KRFB и x11vnc не менялись.

## Проверки сборки 0.0.6-6

Определение схемы мониторов выполняет модуль C, внешний скрипт не устанавливается.
Проверены сборка RPM, отсутствие скриптов и зависимости от интерпретатора,
разбор повреждённых данных и отрицательных координат, захват двух мониторов
5120×1440 на NVIDIA/Wayland.
