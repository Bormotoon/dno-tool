# Сборка медиабиблиотек

Этот каталог используется сборочными командами и не входит в приложение.

| Файл | Назначение |
| --- | --- |
| `windows.py` | Подготовка закреплённых PyAV/FFmpeg для Windows с проверкой SHA-256. |
| `linux.py` | Подготовка общего Qt/PyAV/FFmpeg и сохранение зависимостей из Linux SDK. |
| `bundle.py` | Манифест и состав общего комплекта библиотек внутри PyInstaller. |
| `verify.py` | Аудит пакета и проверка API извлечённых библиотек отдельным процессом. |
| `qt_codecs.py` | Проверка обязательных форматов Qt в сборочном окружении. |
| `runtime_hook.py`, `hooks/` | Необходимые PyInstaller hooks для загрузки общего комплекта. |

Из hooks в приложение попадает только загрузка библиотек, без приёмочных тестов.
Проверка `verify.py` читает обёртки PyAV/Qt из executable и загружает его нативные
модули. Она не требует проверочного режима в `__main__.py` и не открывает профиль
пользователя.

Для подготовки Windows из исходников:

```powershell
.venv\Scripts\python packaging/media/windows.py
.venv\Scripts\python packaging/media/bundle.py manifest
```

Обычные сборки выполняют подготовку и проверки автоматически. Проверки RPM и ELF
находятся в `packaging/linux/verify_rpm.py` и `packaging/linux/audit_elf.py`.
Служебные отчёты сохраняются в `.cache/build-reports/<target>/`; в `dist/`
остаются готовые поставки.

В Linux `libxkbcommon` и `libxkbcommon-x11` копируются из одного пакета SDK.
Версия и SHA-256 обоих файлов сохраняются в манифесте и проверяются после
упаковки. Смешивание core из conda и X11 из системы вызывает падение Qt при
создании окна. Помимо offscreen-проверки сборка запускает Qt через XCB в Xvfb
и проверяет, что обе клавиатурные библиотеки загружены из поставки.
